## Scenario: Dry-run apply emits a complete change plan and mutates nothing

**Status:** PASS

### Steps
- Given the fake provider is loaded from `./fixtures/adapters.json` — fixture written (see "Setup file: fixtures/adapters.json" below)
- And a profile "DOCK 132" exists in `./demo-config/profiles.json` — file seeded before the run (see "Setup file: profiles.json" below)
- Given the fixture has adapter "ad-02" currently in DHCP with address 192.168.1.42/24 and gateway 192.168.1.1 — confirmed by the captured fixture
- And the fixture adapter "ad-02" has macAddress "00-11-22-33-44-55" — confirmed by the captured fixture
- When the user runs `profiles apply --profile "DOCK 132" --adapter ad-02 --dry-run --json`
- Then the exit code is 0 — got 0
- And stdout is a JSON object with kind "ChangePlan" — got "ChangePlan"
- And the change plan's targetAdapterId is "ad-02" — got "ad-02"
- And the change plan's match.confidence is "mac" — got "mac"
- And the change plan's ipv4.from.mode is "dhcp" — got "dhcp"
- And the change plan's ipv4.to.mode is "static" — got "static"
- And the change plan's ipv4.to.address is "192.168.132.10" — got "192.168.132.10"
- And the change plan's ipv4.to.prefixLength is 24 — got 24
- And the change plan's ipv4.willChange is true — got true
- And the change plan's dns.willChange is false — got false
- And the change plan's ipv6.willChange is false — got false
- And the change plan's rollback.snapshotWillBeCreated is true — got true
- And the fake provider mutation log is empty — live FakeProvider.mutationLog.length = 0
